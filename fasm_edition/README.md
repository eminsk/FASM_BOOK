# FASM Edition: Практический Курс и Эталонная Кодовая База (x86-64 Windows)

## 📌 О Проекте

Данная директория (`fasm_edition`) представляет собой **полную профессиональную адаптацию и расширение книги по низкоуровневому программированию** для нативной 64-битной архитектуры **x86-64 Windows** с использованием самого быстрого ассемблера в мире — **Flat Assembler (FASM)**.

Оригинальный репозиторий в корне `D:\proekts\FASM_BOOK` был написан под **ARM64 (Apple Silicon / Linux AArch64)** с синтаксисом GNU Assembler (`.s`, `.S`, GCC/Clang). В отличие от него, настоящая редакция (**FASM Edition**):
- Скомпилирована и проверена на Windows 11 x64.
- Использует автономный компилятор FASM (`tools\fasm\FASM.EXE`) без внешних линкеров, GCC или тяжелых SDK.
- Включает 100% рабочих, протестированных примеров кода для каждого раздела учебника: от базовых конструкций C/C++ до SIMD, многопоточности и нативного GUI.

## 🚀 Быстрый Старт

### 1. Автоматическая сборка всех модулей
Запустите скрипт из командной строки или двойным кликом:
```cmd
cd D:\proekts\FASM_BOOK\fasm_edition
build_all.bat
```
Скрипт найдет и соберет все 25 исходников `*.asm` в бинарные файлы `.exe` и `.dll`.

### 2. Запуск автоматического тестирования
Запустите PowerShell скрипт проверки:
```powershell
powershell -ExecutionPolicy Bypass -File .\test_all.ps1
```
Скрипт автоматически:
1. Компилирует все файлы с контролем возвращаемых кодов.
2. Запускает консольные программы, замеряет время выполнения и проверяет валидность завершения (`ExitCode == 0`).
3. Запускает тест на Python (`test_python.py`), связывающийся через `ctypes` с ассемблерной библиотекой `fast_math.dll`.

### 3. Очистка бинарных файлов
```cmd
clean.bat
```

## 🧠 Ключевые Правила Microsoft x64 Calling Convention

1. **Передача аргументов:**
   - Аргументы 1–4: `RCX`, `RDX`, `R8`, `R9` (целые/указатели) или `XMM0`–`XMM3` (вещественные).
   - Аргументы 5+: передаются через стек по смещениям `[RSP + 32]`, `[RSP + 40]` и т.д.
2. **Shadow Space (Теневое пространство):**
   - Вызывающий код (Caller) обязан выделить минимум **32 байта** в стеке перед командой `call`.
3. **Выравнивание стека (16-Byte Alignment):**
   - В момент передачи управления командой `call` стек `RSP` должен быть строго кратен 16 (`RSP % 16 == 0`).
   - Поскольку сам `call` помещает в стек 8-байтный адрес возврата, на входе в процедуру `RSP % 16 == 8`.
   - Для вызова подфункций стек довыравнивают (например: при отсутствии push'ей `sub rsp, 40`, где 32 байта — теневое пространство, а 8 байт — выравнивание).
4. **Сохраняемые регистры (Non-Volatile):**
   - `RBX`, `RBP`, `RDI`, `RSI`, `R12`–`R15`, `XMM6`–`XMM15`. Если функция их использует, она обязана сохранить их при входе и восстановить перед `ret`.

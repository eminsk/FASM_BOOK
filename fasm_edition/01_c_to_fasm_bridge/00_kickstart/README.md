# Architecture & ABI Kickstart: ARM64 vs x86-64 FASM (Windows)

## 1. Введение
Оригинальная книга в корневом репозитории ориентирована на архитектуру **ARM64 (Apple Silicon / Linux AArch64)** с использованием синтаксиса GNU Assembler (GAS/GCC).

Данная редакция (**FASM Edition**) переносит все фундаментальные концепции книги на нативную архитектуру **x86-64 Windows** с использованием самого быстрого и чистого компилятора ассемблера — **Flat Assembler (FASM)**.

---

## 2. Сравнение архитектур: ARM64 vs x86-64

| Характеристика | ARM64 (AArch64) | x86-64 (Intel/AMD) в FASM |
|---|---|---|
| **Архитектура** | RISC (фиксированная длина 32 бита) | CISC (переменная длина от 1 до 15 байт) |
| **Регистры общего назначения** | `x0` – `x30` (64-бит), `w0` – `w30` (32-бит) | `RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP, R8 – R15` |
| **Указатель стека** | `SP` | `RSP` |
| **Указатель инструкций** | `PC` | `RIP` (доступен RIP-relative: `[rel label]`) |
| **Регистр адреса возврата** | `x30` (`LR` - Link Register) | На вершине стека (команда `ret` снимает адрес) |
| **Операция присваивания** | `mov x0, x1` | `mov rax, rbx` (синтаксис Intel: `dest, src`) |
| **Загрузка из памяти** | `ldr x0, [x1]` | `mov rax, [rbx]` |
| **Сохранение в память** | `str x0, [x1]` | `mov [rbx], rax` |
| **Векторные регистры** | `v0` – `v31` (128-бит NEON) | `XMM0` – `XMM15` (128-бит SSE/AVX) |

## 3. Microsoft x64 Calling Convention (Windows ABI)

В 64-битной Windows действует единый стандарт вызова функций (**FastCall**):

1. **Первые 4 целочисленных/указательных аргумента** передаются через регистры:
   - 1-й аргумент: `RCX`
   - 2-й аргумент: `RDX`
   - 3-й аргумент: `R8`
   - 4-й аргумент: `R9`
2. **Первые 4 вещественных аргумента (float/double)**:
   - Передаются через `XMM0`, `XMM1`, `XMM2`, `XMM3`.
3. **5-й и последующие аргументы**:
   - Помещаются в стек (начиная со смещения `[RSP + 32]`).
4. **Возвращаемое значение**:
   - Целое число или указатель: в регистре `RAX`.
   - Вещественное число: в регистре `XMM0`.
5. **Теневое пространство (Shadow Space / Home Space)**:
   - Вызывающая функция (Caller) **ОБЯЗАНА** выделить в стеке как минимум **32 байта** (`sub rsp, 32` или `sub rsp, 40` с выравниванием) перед любым вызовом функции (`call`). Вызываемая функция может использовать эти 32 байта для сохранения входных регистров.
6. **Выравнивание стека (16-Byte Stack Alignment)**:
   - В момент передачи управления командой `call` стек `RSP` должен быть выровнен по границе 16 байт (`RSP % 16 == 0`). Сама команда `call` помещает 8-байтный адрес возврата, поэтому на входе в функцию `RSP % 16 == 8`. Для вызова следующей функции стек довыравнивают (например: `sub rsp, 40`, где 32 байта — shadow space, а 8 байт — выравнивание: `32 + 8 = 40`).
7. **Сохранение регистров**:
   - **Volatile (Scratch - можно изменять без сохранения)**:
     `RAX`, `RCX`, `RDX`, `R8`, `R9`, `R10`, `R11`, `XMM0` – `XMM5`.
   - **Non-volatile (Обязаны сохранять и восстанавливать при выходе)**:
     `RBX`, `RBP`, `RDI`, `RSI`, `RSP`, `R12`, `R13`, `R14`, `R15`, `XMM6` – `XMM15`.

## 4. Почему FASM (Flat Assembler)?
- **Без линкера**: FASM компилирует исходный код напрямую в готовый исполняемый файл `.exe` или библиотеку `.dll` за 1 проход в памяти! Никаких `link.exe`, `gcc`, `collect2`, промежуточных `.obj` файлов.
- **Полный контроль**: Вы видите каждый байт заголовка PE, секций `.text`, `.data`, `.rdata`, таблицы импорта `.idata`.
- **Максимальная скорость**: Компиляция занимает доли секунды.
